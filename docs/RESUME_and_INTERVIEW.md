## 二、面试话术

### 1) 30 秒版（自我介绍里带过）

> 「我做过一个 ROS2 点云可视化的 demo。自己写了 32 线激光雷达仿真，发布 `PointCloud2`；订阅端自己解
> 消息、做体素降采样，然后用 OpenGL 3.3 Core 加 GLSL 实时画出来——4 万点稳定 60 到 75 帧。
> 整个过程没用 PCL、没用 RViz、也没用 GLEW/GLAD，所以每个环节我都能讲清楚。Windows 和 Ubuntu Foxy
> 两边都跑通了。」

### 2) 3 分钟版（面试官说"讲讲你这个项目"）

按 5 层讲，每层一句话，留接口给他追问：

1. **动机**：「岗位提到 Workbench 桌面应用、渲染引擎、ROS SDK 和点云，我想用一个小而完整的东西证明这
   几块能连起来，所以刻意不用现成库。」
2. **数据链路**：「发布端是我写的雷达仿真，射线和场景图元求交，按 32 线 × 0.25° 出 4 万点，填成
   `PointCloud2`，`point_step=16`、字段偏移 0/4/8/12，QoS 用 `SensorDataQoS`——点云是最新值优先，
   丢旧帧比堆积旧帧好。」
3. **渲染**：「订阅端把消息映射成不依赖 ROS 的只读视图再解码，然后可选体素下采样，`glBufferData` 一次
   传 16 字节/点的顶点，着色器里只有 `vec3 pos + float intensity`，颜色映射放在片元着色器，所以切换
   强度/高度/距离三种模式不重传顶点。点是圆形点精灵，`gl_PointSize` 按透视衰减，远处不会糊成一片。」
4. **验证**：「我没法在 Windows 上跑 ROS，所以做了三层验证：不开 GPU 的逻辑自检 16 项；用带行为的桩头
   文件把真实节点类跑一遍的回环测试 21 项；最后在 Ubuntu 20.04 + Foxy 上真机 colcon build + launch，
   `ros2 topic echo` 看到 `width=41563`，窗口 60 帧。」
5. **边界（主动说）**：「它是个可视化 demo，不是建图系统——没有接 TF 位姿、没做多帧配准、没做 LOD，
   渲染是点精灵不是 3DGS。这些是我下一步想做的。」

### 3) 高频追问与回答要点

| 追问 | 回答要点 |
|---|---|
| 为什么不用 PCL / RViz？ | 「这个 demo 的目的就是证明我自己能写；另外 PCL 会带进来很大一坨依赖，桌面端打包不划算。如果团队已经在用 PCL，我接起来没障碍——体素下采样、PCD 读写这些我理解实现细节，不是只会调 API。」 |
| 为什么是 OpenGL 不是 Vulkan？ | 「先用最熟的 API 把整条管线跑通，把验证和演示做扎实。迁到 Vulkan 要重写上下文/管线/描述符/内存管理四块，我有明确清单：显式同步、command buffer 录制、descriptor set、显存分配器；工作量大概 2–3 天。」 |
| 点云怎么上 GPU 的？ | 「每点 16 字节，`glBufferData` 上传，VAO 两个属性：`vec3` 位置 + `float` 强度；坐标变换和颜色映射在着色器里，CPU 只负责解码和（可选）降采样。」 |
| 100 万点怎么办？ | 「先分块 + 八叉树/视锥裁剪，只传视锥内的块；再有 LOD，远处用体素下采样过的层次；最后才考虑 compute shader 常驻显存做流式。当前 4 万点 0.6 MB，瓶颈会在解码的 CPU 拷贝上——现在测得解码 2.15 ms/帧，还有余量。」 |
| 体素下采样怎么实现的？ | 「21 bit/轴打包成 63 bit 体素键，FNV 混合后做开放寻址线性探测；每个体素累加坐标和强度，最后取均值。40 k 点 1.1 ms，和 PCL 同量级。」 |
| ROS2 里 QoS 为什么这么选？ | 「`SensorDataQoS()` = best_effort + 深度 5。点云是周期性高频数据，丢一帧不影响观感，堆积反而增加延迟；如果是建图要保证不丢，就换 reliable + 大深度或落盘。」 |
| 线程上踩过坑吗？ | 「GL 上下文只能在创建它的线程用，所以 executor 单独线程跑 spin，回调只做解码 + 交接到互斥双缓冲，渲染和上传都在主线程。否则会拿到乱七八糟的 GL 错误或者直接崩。」 |
| 印象最深的 bug？ | 三个都能讲：① GLSL 的 `#version` 必须是第一行，我把调色板函数拼在它前面，编译期不报错、运行时才黑屏；② GL 函数指针声明在全局、定义在 namespace 里，链接期报「无法解析的外部符号 + 已定义且可能匹配的符号」；③ 判断字节序时写反了，自检里三条用例同时挂，一个判断带崩整条链路。 |
| 这个 demo 有什么不足？ | 「不是建图/SLAM，没接 TF 和配准；没有 LOD 和视锥裁剪；HUD 用的是预烘图集，不支持中文；监控指标里 `CPU_UP/CPU_DRAW` 只是 CPU 提交耗时，端到端看 FPS 才准确。」 |
| 你怎么证明发布频率真的是 10 Hz？ | 「`ros2 topic hz` 读出来只有 5.3 Hz，但那不是链路问题：它是 Python 实现，每帧要把 0.65 MB 的 PointCloud2 反序列化成 Python 对象，订阅端跟不上。所以我写了两个对照证据：发布端自己统计实测频率（不是打印参数值），再加一个 C++ 订阅端计数器 `pc_rate_probe`，两边都在 10 Hz 附近，带宽 6.5 MB/s 也对得上 41563 点 × 16 B × 10 Hz。」 |
| 遇到"测量工具不可信"这种问题，你的处理原则？ | 「先分清是**被测对象**有问题还是**测量工具**有问题。这里我先看发布端能否自证（加实测统计），再用不同实现的订阅端做交叉验证；如果三者都不一致，才怀疑链路本身（比如 QoS 丢帧、反序列化慢、DDS 配置）。这条我写进了 README 的验收说明，避免以后有人拿 `hz` 读数当结论。」 |
| 你在这个项目里最想展示什么能力？ | 「把一件跨栈的事从头做完整：C++ 数据结构、GPU 管线、ROS 数据链路、跨平台构建、还有可复跑的验证脚本。不是只写一个能跑 demo 就交差。」 |

### 4) 反问环节可以用的问题（体现你在想工程，不只是做题）

- 「Workbench 现在的渲染是自研管线还是基于现成引擎？如果是自研，渲染后端是 OpenGL 还是已经在往 Vulkan 迁？」
- 「空间智能产品线这边的点云数据源主要是实车雷达还是仿真/回放？桌面端要处理的最大点云规模大概多少？」
- 「团队对『桌面端应用』的技术栈倾向是 Qt 还是别的 UI 框架？渲染窗口是和 UI 同进程还是独立进程？」
